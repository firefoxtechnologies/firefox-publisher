# The Firefox Publisher app

There are two kinds of "app", and they are at different stages.

| | Installable web app (PWA) | Store apps (Android and iPhone) |
|---|---|---|
| Status | **Built and tested** | **Project files are ready. Not built, not published, not live.** |
| Where | Installed from firefoxpublisher.com | Google Play and the App Store |
| Needs | Nothing extra | Developer accounts, Android Studio, a Mac (see below) |

## 1. Installable web app (PWA): done
- `website-react/public/manifest.webmanifest`: name, standalone window, icons (192, 512 and a maskable icon), three shortcuts (cover maker, start a project, audiobooks).
- `website-react/public/sw.js`: pages load network first (visitors get the newest page, the last copy is used offline); hashed files are cached; `/api/` is never cached; `offline.html` is shown when a page has not been saved yet.
- iPhone meta tags are in `index.html`. The Home Screen icon is `apple-touch-icon.png`.
- "Install app" buttons: header (wide screens only), footer, and the open menu. On phones a small card appears at most once a month after about 12 seconds. They hide once the site runs as an installed app. Chrome and Edge install in one tap. iPhone Safari (and browsers that cannot install) show step-by-step help.

What was tested (real Chrome 156 on Windows, built site served locally): the service worker registers and controls the page; Chrome reports no installability errors; with the web server stopped, pages that were visited load fully from the cache and an unvisited page shows the offline page.
What was not tested: install on a real iPhone or Android phone, and the install card on a phone. The service worker could not run in the preview pane inside the Claude app, so the test used Chrome directly.

## 2. Store apps with Capacitor: prepared, not published
`website-react/capacitor.config.json` sets the app id **com.firefoxpublisher.app** and the name **Firefox Publisher**. The `android/` and `ios/` projects were generated by `npx cap add`. They wrap the built site, so the app is the website, plus:
- **Downloads open the phone's Save/Share sheet** (`src/lib/saveFile.js`, using Capacitor Filesystem and Share). Not yet tested on a device.
- The contact form and AI helper call `https://firefoxpublisher.com/api/...` from inside the app (`src/lib/api.js`), and the Worker allows the app origins.

### Build commands
```bash
npm run app:sync --prefix website-react     # builds the site and copies it into android/ and ios/
npm run app:android --prefix website-react  # opens Android Studio
npm run app:ios --prefix website-react      # opens Xcode (Mac only)
```

### What you need (only you can do these)
| | Android / Google Play | iPhone / App Store |
|---|---|---|
| Account | Google Play Console, **$25 once** | Apple Developer Program, **about $99 a year** |
| Tools | Android Studio (free) with a recent JDK | **A Mac** with Xcode (free). iOS apps cannot be built on Windows. |
| New-account rule | Personal accounts created after November 2023 must run a **closed test with at least 12 testers for 14 days** before production release | None of this kind |
| Review | Not instant (often a few days) | Not instant (often 1 to 3 days, sometimes longer) |
| Also needed | Icon, screenshots, privacy policy URL (`/privacy-policy`), content rating, data-safety form | Same, plus App Privacy answers |

Be aware: Apple sometimes rejects apps that are only a website in a frame ("minimum functionality"). The in-app Save/Share sheet, install-free offline use and the cover maker help, but approval is not guaranteed.

### Steps (Android, click by click)
1. Install Android Studio. Open it, choose **Open**, pick the `website-react/android` folder, let Gradle sync.
2. Run `npm run app:sync --prefix website-react` after every website change.
3. **Build > Generate Signed App Bundle / APK > Android App Bundle**. Create a keystore when asked and **keep that file and its password safe and out of git** (`.gitignore` already blocks `*.keystore`/`*.jks`). If you lose it you cannot update the app.
4. In Play Console: Create app > fill the store listing > Testing > Closed testing > upload the `.aab`, add 12 testers, run for 14 days > Production > Create release.

### Steps (iPhone, on a Mac)
1. `cd website-react && npm ci && npm run app:sync`, then `npm run app:ios`.
2. In Xcode choose the **App** target > Signing & Capabilities > select your team (your Apple Developer account).
3. Product > Archive > Distribute App > App Store Connect.
4. In App Store Connect: create the app (bundle id `com.firefoxpublisher.app`), add screenshots and the privacy answers, then submit for review.

## Honest summary
The web app is installable today once the site is deployed. The store apps are **not live** and cannot be made live without your developer accounts, and (for iPhone) a Mac.
